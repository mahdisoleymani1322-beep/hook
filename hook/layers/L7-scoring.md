## 🔁 Layer 7 — Loop امتیازدهی خودکار

### ⚠️ محدودیت بنیادی این لایه — بخوان قبل از استفاده

این امتیازدهی **خودارزیابی** است: همان مدلی که خروجی را ساخته، به آن نمره می‌دهد. نتیجه‌اش این است که معیارهای قضاوتی («تنش دارد»، «باورپذیر است») تقریباً همیشه پاس می‌شوند و عدد نهایی اطلاعات کمی حمل می‌کند.

برای همین معیارها به دو گروه تقسیم شده‌اند:

- **گروه S (شمارش‌پذیر)** — عدد دارند و قابل جعل نیستند. **مقدار اندازه‌گیری‌شده گزارش می‌شود، نه تیک.** نوشتن «✓» به‌جای عدد، خودش فِیل است.
- **گروه J (قضاوتی)** — پاس/فِیل. اعتبارشان مشروط است؛ به آن‌ها به چشم یادآور نگاه کن، نه ضمانت.

عدد نهایی فقط وقتی معنا دارد که **تمام گروه S عدد واقعی گزارش کرده باشند**. اگر می‌خواهی ارزیابی واقعی داشته باشی، خروجی را در یک نشست جدا و بدون تاریخچه‌ی تولید، فقط با همین جدول ارزیابی کن.

هر معیار پاس/فِیل است، نه اسپکتروم. هر پاس = ۱ امتیاز.

**معیار ۱ تا ۲۴ همیشه فعال‌اند.** معیار ۲۵ تا ۲۸ فقط در حالت Narrative (📖 `narrative.md` بخش ۵). دروازه‌های C1–C4 فقط در Case Spine.

### معیارهای مخصوص Case Spine (فقط اگر چارچوب منتخب Case Spine است)

این‌ها **جایگزین امتیاز نیستند — دروازه‌اند.** هر کدام فِیل شود، خروجی تحویل داده نمی‌شود:

- [ ] **C1** قاب کاشف رعایت شده (نه خودستایی مستقیم)؟
- [ ] **C2** حداقل یک اثبات سخت خام (اسکرین‌شات داشبورد / کامنت واقعی / ویدیوی خام) هست؟ *(از پیش در D2 بررسی شده — اینجا فقط تأیید اجرا در شات‌لیست)*
- [ ] **C3** حداکثر ٪۲۰ زمان درباره‌ی خودت/خدمتت است؟
- [ ] **C4** حداقل یک صدای سوم‌شخص (تستیمونیال / کامنت / پیام مشتری) هست؟ *(از پیش در D3 بررسی شده — اینجا فقط تأیید اجرا در شات‌لیست)*

**گروه S — ۱۶ معیار (۱، ۲، ۳، ۵، ۶، ۹، ۱۲، ۱۳، ۱۵، ۱۶، ۱۷، ۱۸، ۲۰، ۲۲، ۲۳، ۲۴):** با **مقدار عددی** می‌آیند. تیک خالی = فِیل.

**گروه J — ۸ معیار (۴، ۷، ۸، ۱۰، ۱۱، ۱۴، ۱۹، ۲۱): پروتکل شاهد اجباری.** هر J فقط با **نقل مستقیم از خروجی** پاس می‌شود:

```
| ۱۴ | J | ✓ | شاهد: هوک «جدول رو درست خوندی» ← ردیف ۱۸–۲۱ همان را حل می‌کند |
```

ادعای پاس بدون نقل = فِیل. نسبت شمارش‌پذیر: **۱۶/۲۴ = ٪۶۷**؛ ۸ معیار باقی شاهد‌محورند، نه تیک‌محور.

هر سه آستانه معادل ٪۸۸ سقف‌اند.

**سقف تلاش:** ۵ تکرار. بعد از آن به کاربر بگو کدام معیار مقاومت می‌کند و چه ورودی بهتری لازم است.

### قوانین سخت‌گیرانه

- **معیار ۱۲ فِیل** → خروجی **تحویل داده نمی‌شود**. Layer 5.5 دوباره اجرا.
- **معیار ۱۸ فِیل** → اگر کمتر از ۶ هوک به دروازه رسیدند، مشکل از هوک نیست، از **زاویه** است. به Layer 1.5 برگرد، نه Layer 2.
- **معیار ۱۹ فِیل** → اگر افشا < ۲۰٪: هوک مبهم است، یک قید مشخص‌کننده اضافه کن. اگر > ۳۰٪: جواب را بردار و به بدنه منتقل کن.
- **معیار ۲۰ فِیل** → اگر تصویر و صدا دو پیام متفاوت می‌دهند، تصویر را با جمله هماهنگ کن (تصویر برنده است، جمله بازنویسی می‌شود).
- **معیار ۲۱ فِیل** → آن جمله بازنویسی شود، نه کل سناریو.
- **معیار ۱۵–۱۷ فِیل** → بازنویسی گام متناظر در Layer 4.7.
- **معیار ۲۳ فِیل** → طول را به بازه‌ی ژانر برگردان. اگر کاربر طول خاصی خواسته که خارج بازه است، **بپرس** — خودسرانه فشرده نکن.
- **معیار ۲۴ فِیل** → گام 4.7.4 اجرا شود. در Case Spine و هر ویدیوی > ۴۵ ثانیه، پیش‌فرض لوپ بازگشتی است.
- **معیار ۱۴ — تست اتصال هوک:** هوک باید ادعایی بکند که بدنه آن را **ثابت یا حل کند**. اگر بتوانی هوک را روی هر ویدیوی دیگری بگذاری و باز هم جواب بدهد → **فِیل**.
