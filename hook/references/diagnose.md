# Diagnose — مود عیب‌یابی، تست A/B و سنجش

> مرجع Layer 8. دو کاربرد دارد:
> - **پیوست خروجی جدید:** برنامه‌ی تست A/B و متریک‌های سنجش، در انتهای هر خروجی `production`
> - **مود مستقل `diagnose`:** وقتی کاربر یک محتوای **منتشرشده** را با آمارش می‌آورد

## بخش ۱ — مود `diagnose` (ورودی: محتوای منتشرشده)

### شرط فعال‌شدن

این مود وقتی فعال می‌شود که کاربر یکی از این‌ها را بیاورد:
- آمار یک ریلز/پست منتشرشده («ویو خورد ولی سیو نداشت»، «نیمه‌ها ریزش داره»)
- اسکرین‌شات اینسایت
- عبارت‌هایی مثل «چرا جواب نداد»، «چرا ویو نگرفت»، «مشکل این ریلز چیه»، «عیب‌یابی کن»

در این مود **Layer 0 تا 6 اجرا نمی‌شود.** خروجی یک تشخیص است، نه یک سناریوی جدید — مگر اینکه کاربر بازسازی هم بخواهد.

### ورودی‌های لازم (اگر نبود، حداکثر ۳ سؤال بپرس؛ اگر کاربر نداشت، به شاخه‌ی نسبت‌محور برو — تشخیص را رها نکن)

| ورودی | چرا لازم است |
|---|---|
| هوک و ۳ ثانیه‌ی اول (متن یا توصیف) | منبع ۶۰٪ مشکلات |
| طول ویدیو + GOAL اعلامی | مبنای قضاوت |
| حداقل دو عدد از: نگهداشت، میانگین تماشا، سیو، شیر، کامنت، ویو | بدون عدد، تشخیص حدس است |

### آستانه‌های عددی — طبقه‌بندی علامت

طبقه‌بندی علامت باید عددی باشد، نه شهودی. ابتدا نسبت‌ها را محاسبه کن، بعد وارد جدول تشخیص شو.

| سنجه | محاسبه | بحرانی | ضعیف | سالم | قوی |
|---|---|---|---|---|---|
| نگهداشت ۳ ثانیه | بیننده‌ی ثانیه ۳ ÷ ویو | < ۴۵٪ | ۴۵–۶۰٪ | ۶۰–۷۵٪ | > ۷۵٪ |
| نرخ تکمیل | میانگین تماشا ÷ طول | < ۲۵٪ | ۲۵–۴۰٪ | ۴۰–۶۰٪ | > ۶۰٪ |
| نرخ سیو | سیو ÷ ویو | < ۰.۵٪ | ۰.۵–۱٪ | ۱–۳٪ | > ۳٪ |
| نرخ شیر | شیر ÷ ویو | < ۰.۳٪ | ۰.۳–۱٪ | ۱–۳٪ | > ۳٪ |
| نرخ اقدام | کامنت+کلیک ÷ ویو | < ۰.۲٪ | ۰.۲–۰.۵٪ | ۰.۵–۲٪ | > ۲٪ |

**قاعده‌ی انتخاب علامت غالب:** پایین‌ترین سنجه نسبت به باند سالمش، علامت غالب است. اگر دو سنجه هم‌تراز بحرانی‌اند، **نگهداشت ۳ ثانیه اولویت دارد** — چون بقیه‌ی سنجه‌ها پایین‌دست آن‌اند.

**مثال:** ویو ۱۲۰۰۰ · سیو ۹۰ · نگهداشت ۳s ۶۲٪ · میانگین ۸s از ۲۸s
→ نگهداشت ۶۲٪ سالم · تکمیل ۲۸.۶٪ ضعیف · سیو ۰.۷۵٪ ضعیف
→ علامت غالب: **شروع خوب، افت در بدنه** — هوک کار کرده، بدنه وعده را تحویل نداده

### شاخه‌ی نسبت‌محور — وقتی نگهداشت و ویو در دست نیست

اغلب کاربر فقط شمارنده‌های تعامل را دارد (لایک، کامنت، شیر، سیو) بدون نگهداشت و گاهی بدون ویو. در این حالت **تشخیص متوقف نمی‌شود** — به نسبت‌ها منتقل می‌شود.

```
ورودی حداقلی این شاخه: سه عدد از چهار (لایک، کامنت، شیر، سیو)
خروجی: تشخیص نوع محتوا و تطابق آن با GOAL — نه تشخیص نقطه‌ی ریزش
```

| نسبت | معنا | اقدام |
|---|---|---|
| شیر > لایک | محتوای B2B / تصمیم‌محور | GOAL باید `share` یا `sale` ثبت شود، نه `view` |
| سیو > شیر | ارزش کاربردی بدون لایه‌ی هویتی | Layer 1.5 — افزودن موضع‌گیری |
| کامنت > سیو | موضع‌گیری دارد، ارزش مرجع ندارد | Layer 5.5 محرک ۸ یا ۹ |
| لایک >> بقیه | مصرف منفعل؛ محتوا کاری از مخاطب نخواسته | Layer 5.5 — CTA فاقد triple |
| هر چهار پایین و نزدیک | مشکل از توزیع یا کاور است، نه بدنه | کانال متنی + کاور |

**قید صریح:** این شاخه نمی‌تواند بگوید ریزش در کدام ثانیه رخ داده. اگر کاربر نگهداشت ندارد، این را در یک خط اعلام کن و تشخیص را به سطح نسبت محدود کن — حدس‌زدن نقطه‌ی ریزش بدون داده ممنوع است.

### جدول تشخیص — علامت → علت → اصلاح

| علامت | علت محتمل | لایه‌ای که باید بازنویسی شود |
|---|---|---|
| **افت شدید در ۳ ثانیه‌ی اول** | هوک کند، مبهم، طولانی یا ناهماهنگ با کاور/عنوان | Layer 2 + کانال بصری (`hook-qc.md` بخش ۵) |
| **شروع خوب، افت در بدنه** | وعده جذاب بوده ولی پاسخ دیر یا پراکنده ارائه شده | Layer 4.7 گام 4.7.1 (زنجیره‌ی Micro-Reward) |
| **افت دقیقاً در میانه** | ریتم خوابیده، هیچ نقطه‌ی ریستی نیست | Layer 4.7 گام 4.7.2 (Re-Hook) |
| **تماشا خوب، اقدام کم** | CTA مبهم است یا به مرحله‌ی بعدی طبیعی وصل نمی‌شود | Layer 5.5 (triple) |
| **ویو بالا، اعتماد پایین** (کامنت منفی، آنفالو) | ادعا بزرگ‌تر از محتوای تحویلی بوده | دروازه‌ی اخلاقی + فیلتر ضد-گورو |
| **سیو بالا، شیر کم** | محتوا مفید است ولی هویت یا احساس جمعی ندارد | Layer 1.5 (زاویه) — زاویه‌ی موضع‌گیری یا تضاد |
| **شیر بالا، سیو کم** | احساسی است ولی ارزش کاربردی قابل بازگشت ندارد | Layer 5.5 — محرک ۸ یا ۹ (ارزش مرجع / حلقه‌ی عملی باز) |
| **بازپخش غیرعادی بالا** | یا جذاب است یا بیش از حد سریع و نامفهوم — کامنت‌ها را بخوان | Layer 4.7 گام 4.7.3 (کادنس) |
| **ویو پایین با نگهداشت خوب** | مشکل از محتوا نیست، از توزیع/کاور/عنوان است | کانال متنی + کاور |
| **بازپخش پایین در ویدیوی بلند** | پایان بسته است و دلیلی برای دیدن دوباره نمی‌دهد | Layer 4.7 گام 4.7.4 — لوپ بازگشتی |

### الگوهای متریکی که خودشان تشخیص‌اند

- **شیر > لایک** (مثلاً ۱۵۰۰ شیر در برابر ۷۰۰ لایک) → امضای محتوای **B2B یا تصمیم‌محور**. آدم‌ها لایک نمی‌کنند، برای همکار/شریک می‌فرستند. متریک تصمیم‌گیر این محتوا **شیر** است، نه ویو — و GOAL باید `share` یا `sale` ثبت شود، نه `view`.
- **سیو > شیر** → ارزش کاربردی دارد ولی لایه‌ی هویتی ندارد
- **کامنت > سیو با ویو متوسط** → محتوا موضع‌گیری دارد؛ برای `cta_engagement` عالی، برای `save` ضعیف

### قانون طلایی اصلاح

> **هر بار فقط یک متغیر را عوض کن.**

جمله‌ی هوک، تصویر اول، سرعت، شاهد، یا CTA — یکی. وگرنه نمی‌فهمی کدام تغییر اثر گذاشت.

### 🔐 دروازه‌ی پیش‌تحویل مود diagnose

Layer 9 در این مود اجرا نمی‌شود، پس این دروازه‌ی جایگزین آن است. ۶ بند، قبل از نمایش هر تشخیص:

```
[ ] ۱ هر پنج سنجه‌ی عددی محاسبه و باندشان اعلام شده
[ ] ۲ علامت غالب با قاعده‌ی انتخاب تعیین شده، نه شهودی
[ ] ۳ هر علت با شاهد عددی مشخص پشتیبانی شده
[ ] ۴ دقیقاً یک متغیر برای تغییر انتخاب شده — نه دو تا
[ ] ۵ نسخه‌ی اصلاح‌شده تولید شده، نه فقط توصیه
[ ] ۶ متریک سنجش نسخه‌ی بعد نام برده شده
```

**خط گزارش اجباری:** `✔ دروازه‌ی تشخیص: ۶/۶ · نگهداشت_٪ · تکمیل_٪ · سیو_٪ · شیر_٪ · اقدام_٪`

## بخش ۲ — برنامه‌ی تست A/B (پیوست هر خروجی جدید)

**اصل:** برای هر ایده، **۳ زاویه‌ی متفاوت** بساز و تست کن — نه سه بازنویسی یک زاویه.

### پروتکل

1. یک محتوای ثابت انتخاب کن
2. سه هوک از **سه زاویه‌ی متفاوت** بنویس (درد / تضاد / نتیجه — یا هر سه‌تای دیگر از Layer 1.5)
3. بدنه، طول، زمان انتشار و CTA را **تا حد ممکن ثابت** نگه دار
4. هر نسخه را در نمونه یا بازه‌ی قابل‌مقایسه تست کن (استوری هم برای پیش‌تست کافی است)
5. نگهداشت ابتدای ویدیو، میانگین تماشا و اقدام نهایی را مقایسه کن

### مثال سه زاویه برای یک موضوع

```
مشکل:   «چرا پرامپتت خروجی مصنوعی می‌ده؟»
نتیجه:  «این سه تغییر، خروجی رو طبیعی‌تر می‌کنه»
آزمایش: «یک تصویر رو با سه مدل پرامپت ساختم؛ تفاوت رو ببین»
```

### فرمت خروجی (انتهای هر خروجی `production`)

```markdown
**برنامه‌ی تست:**
- نسخه A (زاویه ...): «...»
- نسخه B (زاویه ...): «...»
- نسخه C (زاویه ...): «...»
- متغیرهای ثابت: بدنه، طول ...s، CTA، ساعت انتشار
- معیار برنده: ...
```

> **قانون:** ۳ هوک جایگزین در خروجی باید همین سه نسخه باشند — از سه زاویه‌ی متفاوت، نه سه تغییر جمله‌بندی روی یک زاویه. این معیار ۲۲ در Layer 7 است.

## بخش ۳ — متریک‌هایی که باید بررسی شوند

| متریک | چه چیزی را می‌سنجد | نشانه‌ی خطر |
|---|---|---|
| **نگهداشت** | چند درصد بعد از شروع ماندند | افت تند ابتدایی = هوک مبهم/کند/نامرتبط |
| **میانگین تماشا و ٪ تکمیل** | بدنه چقدر وعده‌ی هوک را تحویل داده | تکمیل پایین با شروع خوب = بدنه ضعیف |
| **بازپخش** | جذابیت یا نامفهومی | باید با خود ویدیو کنار هم خوانده شود |
| **اشتراک** | ارزش کاربردی، هویت یا احساس فعال | شیر صفر با سیو بالا = بدون لایه‌ی هویتی |
| **اقدام** (کامنت/کلیک/سیو/خرید) | تحقق GOAL | باید با GOAL سنجیده شود، نه با ویو |

**قانون:** ویو بالا همیشه موفقیت نیست. متریک سنجش، همان **تعریف موفقیت اجرایی GOAL** در Layer 0 است، نه چیز دیگری.

### نگاشت GOAL → متریک اصلی

| GOAL | متریک تصمیم‌گیر |
|---|---|
| `view` | ویو ۲۴ ساعت اول نسبت به تعداد فالوور |
| `follow` | نرخ فالو از غیرفالوور |
| `sale` | کلیک لینک / دایرکت خرید |
| `cta_engagement` | تعداد کامنت/دایرکت قابل ردیابی |
| `save` | نرخ سیو نسبت به ویو |
| `share` | نرخ شیر نسبت به ویو |

## بخش ۴ — آرشیو برنده‌ها

بعد از هر تست، الگوی برنده را ثبت کن:

```
موضوع: ... · زاویه‌ی برنده: ... · دسته‌ی هوک: ... · نگهداشت ۳ ثانیه: ...٪
چرا برد (فرضیه): ...
سه موضوع دیگری که همین الگو رویشان جواب می‌دهد: ...
```

هدف، پیدا کردن **زبان مخاطب خودت** است — نه یک جمله‌ی ثابت برای همه‌ی محتواها. بعد از ۳ تا ۵ تست، الگوی غالب نیچ کاربر معلوم می‌شود و باید در ورودی‌های بعدی به‌عنوان context استفاده شود.
